## 1. 支付 / 订阅 / 积分

### 1.1 支付网关抽象(端口)

`payment/payment.go` 定义了网关核心接口,是「一次付款=一个 Checkout」的指向:

```go
// payment.go:157-163
type CheckoutCreator interface {
	CreateCheckout(context.Context, CheckoutRequest) (CheckoutAction, error)
}
type CheckoutResumer interface {
	ResumeCheckout(context.Context, CheckoutResumeRequest) (CheckoutAction, error)
}
```

关键数据结构(均带 JSON tag,直接映射前端):

- `CheckoutRequest`(`payment.go:91-103`):`OrderID / MerchantOrderID / Name / AmountMinor / Currency / TaxCategory / UserID / UserEmail / NotifyURL / SuccessURL / CancelURL`。金额一律使用**最小货币单位整数**(`AmountMinor int64`)。
- `CheckoutAction`(`payment.go:117-127`):`Type(redirect|form_post) / URL / Fields / ResumeMode / ProviderOrderID / SessionID / SessionURL / ExpiresAt`。前端据此跳转或提交表单。
- `ProviderEvent`(`payment.go:129-150`):把各厂商回调归一化的统一事件,含 `Status(paid|processing|failed|expired|ignored)`、`AmountMinor`、`PaidAmountMinor`、`TaxAmountMinor`、`Currency`、`OrderID`、`ProviderOrderID`、`ProviderPaymentID`。
- 提供商标识常量:`ProviderStripe / ProviderEPay / ProviderWaffo`(`payment.go:57-61`),税目 `digital_goods | saas`(`payment.go:152-155`)。

**关键设计——「状态未知」分类(`IsCheckoutStateUnknown`, `payment.go:27-55`)**:当请求超时/连接重置/5xx 时,无法确定厂商是否已接受请求,于是订单进入 `processing` 以便后续**对账(reconcile)**,而不是直接标记失败(避免重复扣款)。这是支付可靠性的核心,复刻时必须保留。

### 1.2 货币与金额工具(`payment/money.go`)

- `CurrencyExponent`(`money.go:25-37`):按 ISO 4217 区分零/三/四位小数货币(JPY=0、BHD=3、CLF=4、默认 2)。
- `FormatMinorAmount` / `ParseMinorAmount`(`money.go:39-88`):最小单位 ↔ 字符串。
- `NormalizeConversionRate` / `ConvertMinorAmount`(`money.go:94-168`):跨币种换算,用 `math/big` 防浮点误差,四舍五入到目标最小单位;税率/汇率存为**不可变订单快照**而非读可变配置。

### 1.3 三家网关实现

#### Stripe(`payment/stripe.go`)
- `StripeConfig`:`SecretKey` + `WebhookSecret`(`stripe.go:16-19`)。
- `CreateCheckout`(`stripe.go:58-105`):调用 `stripe.go/v86` SDK,创建**一次性 Payment Checkout Session**(非订阅模式):
  - `Mode = CheckoutSessionModePayment`(单次付款,不是 recurring)。
  - 全部金额以 `UnitAmount` 最小单位、`Quantity=1` 单个 line item。
  - `ClientReferenceID = OrderID`;在 Session 与 PaymentIntent 的 `metadata["order_id"]` 冗余存 `OrderID`(`stripe.go:73,86-87`),用于对账/找回。
  - `integration_identifier = "aivory_"+sha256(orderID)`(`stripe.go:164-171`)。
  - 设置 `IdempotencyKey = OrderID`(`stripe.go:88`),防重复下单。
  - 返回 `session.ID` 作为 `ProviderOrderID`/`SessionID`,`ExpiresAt` 保留。
- `ResumeCheckout`(`stripe.go:110-162`):**只 retrieve 原 Session 并做严格校验**——校验 `ClientReferenceID`/metadata 归属、`Mode==payment`、状态 `open`+`unpaid`、未过期;校验失败**不私自重建 Session**(要求另记一次支付尝试),`SessionURL` 永不内嵌短期凭据。
- Webhook 验签:`VerifyStripeEvent`(`stripe.go:290-311`)用 `whsec_` 密钥 `ConstructEventWithOptions(..., IgnoreAPIVersionMismatch: true)`,处理 `checkout.session.completed / expired / async_payment_succeeded / async_payment_failed`,归一成 `checkout.session.reconciled` 等 ProviderEvent。
- 对账 `Reconcile`(`stripe.go:173-205`):优先用本地 Session 快照;当超时导致无 Session ID 时,用 metadata 搜索 PaymentIntents 再反查 Session(`retrieveStripeReconciliationSession`, `stripe.go:213-255`),**搜索是有限且有界**的,索引未追平时报 state-unknown。

#### EPay(`payment/epay.go`)— 中国第三方支付(alipay 类网关)
- `EPayConfig`:`GatewayURL / MerchantID / MerchantKey / Currency / ConversionRate / ConversionRateBaseCurrency`(`epay.go:17-24`)。
- `CreateCheckout`(`epay.go:109-151`):构造 `submit.php` 的 `application/x-www-form-urlencoded` 表单 POST(`ActionFormPost`),字段 `pid/type/out_trade_no/notify_url/return_url/name/money/device/sign_type=MD5/sign`。
- 签名 `EPaySign`(`epay.go:171-192`):把参数(除 `sign`/`sign_type`)**字典序**拼接成 `k=v&k=v` + 商户 key,M D5 hex。验签用 `subtle.ConstantTimeCompare` 防时序攻击(`epay.go:197`)。
- EPay 用**大单位字符串**金额(`money` 字段),由 `VerifyEPayEvent` 校验后由 `normalizeProviderEventForOrder` 用订单快照币种解析(`payment_handlers.go:752-765`)。
- EPay 没有 session 恢复协议,`ResumeCheckout` 重新生成**同一个 merchant order ref** 的签名表单,`ResumeMode=retry_submission`(`epay.go:158-169`)。
- 需要 `PaymentOrderAttempt`(merchant 订单引用表)以支持重试防重(`payment_handlers.go:194-204`)。

#### Waffo Pancake(`payment/waffo.go`)— 第二套国际卡/加密网关(SDK `waffo-pancake-sdk-go`)
- `WaffoConfig`:`MerchantID / PrivateKey / StoreID(STO-xxx) / ProductID(PROD-xxx) / Currency / ConversionRate / Mode(test|prod) / WebhookPublicKey`(`waffo.go:19-29`)。
- 用 GraphQL API,30s 超时(`waffoCheckoutTimeout`, `waffo.go:17`);`WaffoReconciler.Reconcile`(`waffo.go:294`)按订单对账。
- Webhook 验签 `VerifyWaffoEvent`(`waffo.go:446`)用 `X-Waffo-Signature` + 公钥。
- 其金额换算回 `money.go` 的 `ConvertMinorAmount`,并针对「厂商币种 ≠ 结算币种」在 fulfillment 阶段保留结算快照(`payment_handlers.go:696-701`)。

> 三家网关共享同一 `CheckoutCreator/Reconciler` 抽象,由 `api/payment_config.go:334 paymentGateway()` 依据 provider 选择;`api/payment_handlers.go` 的商业逻辑与厂商无关。**复刻时请依赖抽象,而非某个具体 SDK。**

### 1.4 下单 API 流程(`api/payment_handlers.go`)

`createPaymentCheckoutHandler`(`payment_handlers.go:142-258`)完整链路:

1. 请求体:`payment_method_id + target_type + target_id + billing_cycle`。
2. `store.CreatePaymentOrder(...)`(`payment_handlers.go:161` 及 `store/payments.go:810`)——在本地一次事务内校验商品/用户/通道方法可用性,**生成订单金额/币种快照**,返回 `Provider / AmountMinor / ProviderCurrency / ChannelID`。
3. 读取通道 + 构建网关(`payment_handlers.go:180-193`);EPay 额外创建 `PaymentOrderAttempt`(merchant 订单号)。
4. 用 `paymentDetachedContext`(脱离请求 ctx、带超时,`payment_handlers.go:260-262`)调用厂商 `CreateCheckout`,回跳 URL 指向 `/subscription?payment=return&order={id}`(`payment_handlers.go:206-222`)。
5. 出错时:区分「厂商状态未知」(→`MarkPaymentOrderProcessing`)与「确定失败」(→`MarkPaymentOrderFailed`)(`payment_handlers.go:224-236`)。
6. 校验 action 后 `persistPaymentCheckoutAction` 持久化 provider/session 快照(`payment_handlers.go:245-257`);**回给前端的 action 剥掉 `ProviderOrderID/SessionID/SessionURL/ExpiresAt`**(仅前端可见安全字段)。

`listPaymentMethodsPublic`(`payment_handlers.go:97-140`):列出启用通道/方法,`test` 环境仅 admin 可见,并校验币种支持。

### 1.5 Webhook 与履行(Fulfillment / 发积分)

`paymentWebhookHandler`(`payment_handlers.go:581-626`) → `verifyProviderWebhook`(按 provider 验签)→ `applyProviderEvent`(`payment_handlers.go:665-750`)。

`applyProviderEvent` 是兑现核心:
- 先按 `event.OrderID`(EPay merchant ref)或 providerOrderID/providerPaymentID 定位订单(幂等)。
- **`EventPaid`** 时归一化金额(EPay 用结算快照、Waffo 跨币种保留结算快照),调用 `store.FulfillPaymentOrder`(`payment_handlers.go:703-707`)。
  - 若 `ProductType == PaymentProductUserGroup`,则发「会员生效」邮件并推送权限事件(`payment_handlers.go:712-716`)。
- 非 paid 事件写入 `payment_events` 表,并按状态转移订单(`processing/failed/expired`)(`payment_handlers.go:721-749`)。

`store.FulfillPaymentOrder`(`store/payments.go:1818-2096`)是**事务化**的兑现:
1. `markPaymentOrderAttemptPaid` + 插入 `payment_events`(`ON CONFLICT(provider,channel_id,event_id) DO NOTHING` 防重复);重复事件则幂等返回 `DuplicateEvent`(`payments.go:1852-1881`)。
2. 校验订单归属/金额/币种/ProviderPaymentID(多处一致性校验,`payments.go:1887-1912`)。
3. 加行锁 `SELECT ... FOR UPDATE`(`payments.go:1943-1954`),按 `ProductType` 分发:
   - **`credit_package`**:校验 `Credits>0` 且无 group/cycle,`addPermanentCreditsMicrosTx` 给用户加**永久积分**(`payments.go:1957-1970`)。
   - **`user_group`**:校验 monthly/yearly 计费周期,计算 `group_id / group_expires_at / previous_group_id / credit_cycle_anchor / quota_cycle_anchor`,处理**当前有效套餐的续费叠加**(`base = currentExpiry`)与**套餐切换**(保留永久基线于 `previous_group_id`)(`payments.go:1971-2045`)。
4. 原子地把订单置为 `fulfilled` + `paid_at / fulfilled_at`(`payments.go:2058-2074`)。

### 1.6 订阅/套餐如何运作(Subscription 生命周期)

**不是 Stripe 订阅**,而是「本地订单驱动的限时套餐」:

- 两种商品:`PaymentProductCreditPackage`(积分包,一次性)与 `PaymentProductUserGroup`(会员用户组,monthly/yearly)。
- `user_groups` 表:`monthly_price_amount_minor / yearly_price_amount_minor`(最小单位)+ `credit_allowance / credit_period_seconds`(组内周期积分额度)(`store/user_groups.go:53`)。**价格与积分额度都在本地数据库,供应商只负责收钱。**
- 每次购买是独立的 Checkout(单次付款)。**没有自动续费/扣款卡;**「订阅」的续费是在套餐到期后再次购买或提前叠加。
- 到期 = `group_expires_at` 字段。`FulfillPaymentOrder` 中处理:
  - 若 `currentExpiry > now`(仍有效)且买的是同一个组 → 从 `currentExpiry` 续期(`base = currentExpiry`, `payments.go:2012-2014`);
  - 若既永久又切到别组 → 原组存进 `previous_group_id` 作永久基线(`payments.go:2015-2021`);
  - 永久组(`base=0`)→ `group_expires_at=0` 表示长期有效。
- **周期积分额度**:`user_groups.credit_allowance` + `credit_period_seconds`,用户余额在 `credit_ledger` 按 `cycle_anchor/cycle_start` 记账,`CreditCycleStart` 计算当期窗口(`store/credits.go:91-104`)。
- **管理端对账**:`reconcilePaymentOrderAdmin`(`payment_admin_handlers.go:662`)与 `Reconciler.Reconcile` 用于「状态未知」订单的兜底对账,以及关闭超时 checkout(expire session)。

### 1.7 积分(Credits)账本(`store/credits.go`)

积分体系非常完整,理解它=理解计费扣减:

- **两类积分**:
  - `Permanent`(永久):购积分包所得,存 `users.credits_permanent_micros`。
  - `Timed`(周期):套餐组附带的周期额度,存 `credit_ledger`(`kind=timed_debit`)按周期结算。
- **内部一律用微单位整数**(`CreditMicrosPerUnit = 1_000_000`, `credits.go:13`),`CreditsToMicros` 用 `math.Round` 且防 NaN/Inf/越界(`credits.go:73-85`)。
- **余额计算** `creditBalanceFrom`(`credits.go:116-183`):`Available = (timedRemaining + permanent) - reserved`,并 `FOR UPDATE` 行锁(Postgres)。
- **扣减** `debitCreditsTx`(`credits.go:189-252`):先扣 timed,再扣 permanent;写入 `credit_ledger`(timed 与 permanent 各一行),保证「先周期性额度后永久积分」。
- **预留(Reservation)模式**——计费原子性:
  - `ReserveCredits`(`credits.go:274-335`):生成生成任务前先「冻结」金额(默认 TTL 6h),写 `credit_reservations(status=reserved)`。
  - `SettleCreditReservation`(`credits.go:361-403`):生成完成后按**实际**计费结算,冲销预留、真正扣减。
  - `SettleCreditReservationByKey`(`credits.go:433-539`):最终计费键在任务后才知晓(如上游返回的 doc id),在事务内重设键 `re-key`,保证「同一工作量只扣一次」,重复事件退款。这是防止重试双扣的核心。
  - `ReleaseCreditReservation`(`credits.go:405-410`):失败/停止时释放。
- 状态机:`reserved → settling → settled|released`(`credits.go:15-22`)。

### 1.8 兑换码(Redeem)(`store/redeem_codes.go`)

- `RedeemCode`(`redeem_codes.go:37`):code、类型、积分/会员天数、批次、唯一性(模糊唯一,`redeemCodeUniquenessRetries=5`)。
- `BulkGenerateRedeemCodes`(`redeem_codes.go:156`):批量生成。
- `RedeemCodeForUser`(`redeem_codes.go:387`):核心兑换——校验未用、归属、`confirm` 二段确认(`checkedRedeemExpiry` 计算会员到期),写 `redemptions` 表 + 加 credits / 加会员组,处理并发(`redeem_concurrency_test.go` 覆盖)。

### 2.2 邮件类型与路由(DeliveryConfig)
- 支持类型:`verify / reset / welcome / membership`(`delivery_config.go:23`)。
- `DeliveryConfig`(`delivery_config.go:41-44`):多 `SMTPAccount`(host/port/user/password/from/tls)+ 每类型 `Rules`(account_id + enabled)——**可为不同邮件类型指定不同 SMTP 账户**。
- 安全约束:
  - `verify`/`reset` 为 `RequiredPurpose`,**不可被禁用**(`delivery_config.go:46,184-186`)。
  - 密码用 `••••••` 掩码,同 ID 复用旧密码(`NormalizeDeliveryConfig`, `delivery_config.go:131-193`)。
  - `validateSMTPAccount` 严格校验 host/port/credential header 注入(`delivery_config.go:195-217`)。
- 兼容旧式 `smtp_*` 扁平设置(`LoadDeliveryConfig`, `delivery_config.go:74-124`)。
- `SecurityReady(db)`(`delivery_config.go:257-265`):校验 verify/reset 两类都已配置。

### 2.3 发信(`mail.go:85-184`)
- 手工构造 MIME:UTF-8 `mime.QEncoding` 主题、`quoted-printable` HTML 正文(`mail.go:100-111`)。
- 用 `net/smtp` + `crypto/tls`,关键细节:
  - 端口 `465` 或 `TLS=true` → 隐式 TLS;否则 `587/25` 先明文再 `STARTTLS` 自动升级(`mail.go:125-156`)。
  - **每个网络步骤都设超时**:`net.Dialer{Timeout:10s}` + 整体 `SetDeadline(25s)`,避免错误端口/TLS 模式不匹配导致永久挂起(`mail.go:121-122`)。
  - 配置了用户名且服务器支持 `AUTH` 才认证(`mail.go:160-166`)。
- `CheckDomainWhitelist`(`mail.go:188-222`):按管理员 `email_domain_whitelist` 校验注册域名,空=全允许。
- 安全测试 `mail_security_test.go`:校验不泄漏验证码/重置 URL/token(从不记录这些字段)。

### 2.4 模板(Go `html/template`)
- `templates.go:renderAuthEmail`(`templates.go:76-115`)按 `Purpose` 取 `verify`(展示验证码)/`reset`(展示按钮+链接),`reset` 链接必须合法(http/https、有 host、无 userinfo)。
- `account_templates.go:renderAccountEmail`(`account_templates.go:53-88`):`welcome`(引导按钮+功能列表)/`membership`(组名+有效期至)。
- **5 种语言硬编码文案**:`zh / zh-Hant / en / ja / fr`(`templates.go:39-65`、`account_templates.go:20-51`);`NormalizeLocale`(`templates.go:15-31`)规范化语言标签。
- 模板是一个**内联 HTML 字符串**(`emailTmpl`, `templates.go:119-140`),用 Table 布局 + 内联样式,保证在任意客户端渲染;品牌色编译为字面值。
- `Preview(AuthMessage)`(`templates.go:143`)复用同一渲染而不发信。

## 3. 缓存抽象(`cache/`)

### 3.1 `Cache` 接口(`cache.go:20-56`)— 最小但完整
- **KV**:`Get(cache.go:21) / Set(cache.go:25) / Delete(cache.go:31) / TTL(cache.go:34)`。
- **原子一次性消费**:`Take`(取即删,`cache.go:23-25`,用于一次性凭证)、`SetNX`(`cache.go:27`)、`CompareAndDelete`(`cache.go:29-31`,校验再删,用于验证码消费)。
- **原子计数**:`Incr(cache.go:35) / IncrBy(cache.go:39) / Decr(cache.go:41)`。
- **Pub/Sub**:`Publish / Subscribe`(`cache.go:42-43`)。
- **Stream(追加型事件流)**:`StreamAppend / StreamRead / StreamAppendIfAllowed / StreamReadIfAllowed / StreamRevoke`(`cache.go:44-55`)——用于生成流(SSE)的跨实例分发与**访问撤销**(`denyKeys` 墓碑)。

### 3.2 内存实现(`cache.go:73-463`)
- `memory`(线程安全,`sync.RWMutex`):`store map[string]memoryEntry`(value+exp)+ `subs` + `streams map[string]memoryStream`。
- 语义与 Redis 对齐,便于开发/测试互换:`SetNX`、`Take`、`CompareAndDelete`、固定窗口 `Incr`(TTL 仅在首次创建时应用,`cache.go:190-207`)。
- Stream 用 `时间戳-自增序列` 作 ID(`cache.go:319-320`),容量上限 50000 事件(`cache.go:328`)。
- 调参暴露为 `AIVORY_*` 环境变量(`cache.go:12-16`)。

### 3.3 Redis 实现(`cache.go` → `redis.go`)
- `NewRedis(url string)`(`redis.go:98-111`):`redis.ParseURL` + `Ping` 快速失败。
- 每个命令都有 `redisOpTimeout = 3s`(`redis.go:18`)。
- **关键:用 Lua 脚本保证原子性**:
  - `incrWithTTLScript`(`redis.go:20-26`):INCR + 仅当 n==1 时 PEXPIRE(固定窗口)。
  - `takeScript`(`redis.go:28-35`)、`compareAndDeleteScript`(`redis.go:37-42`)。
  - Stream 类:先 `EXISTS` 检查所有 `denyKeys`,命中则拒绝(撤销语义),再 `XADD ... MAXLEN ~ 50000` / `XRANGE ... COUNT`(脚本,`redis.go:44-89`)。
- `Subscribe`(`redis.go:226-280`):**跨进程订阅**——一个 API 实例 `Publish` 的 stop/kill/配置失效信号能到达所有实例(多副本下实时封禁、停止生成流)。实现上先 `ps.Receive` 等 SUBSCRIBE 确认(防丢失首条信号,`redis.go:233-241`),并由单一 bridge goroutine 关闭 channel 防 panic(`redis.go:246-269`)。
- 用途示例(注释,`cache.go:1-7` / `redis.go:1-6`):配置失效广播、`kill`/停止生成流、实时封禁(`§8.1`)、`stop-stream`(`§11.5`)。

> 复刻要点:定义 `Cache` Protocol(typing.Protocol),提供 `MemoryCache` 与 `RedisCache` 两个实现,`Incr/Stream*/Take` 必须原子(Redis 用 Lua 或 `redis-py` 的 pipeline/脚本;内存版用 asyncio.Lock)。

## 5. 上传安全(`fileguard/` + `api/upload_policy.go`)

### 5.1 `fileguard` — 文件系统路径包含性校验
`fileguard.go` 是针对「数据库值 ≠ 可信文件系统路径」的防御(备份恢复、对象删除等):
- `Relative(root,path)`(`fileguard.go:18-37`):**纯词法**校验 path 严格位于 root 内(可校验另一台机器的备份路径)。
- `Remap`(`fileguard.go:41-54`):把 sourceRoot 下路径映射到 targetRoot。
- `ResolveExisting`(`fileguard.go:59-101`):词法 + `EvalSymlinks` 双重校验,**拒绝 FIFO/socket/设备等特殊文件**,只允许 regular file。
- `PrepareWrite`(`fileguard.go:106-162`):安全创建目录(逐段 Lstat,拒绝 symlink),既防符号链接逃逸又防写入特殊文件。
- `storage_lock.go`:跨进程存储锁(`LockStorage`, `storage_lock.go:104-154`)——基于 root 旁的 `.aivory-storage-<hash>.lock` 文件 + OS 级 flock(`tryLockStorageFile` 分 unix/windows 实现),协调备份/恢复与文件写入/清理;`RequireStorageRecovery`(`storage_lock.go:50-73`)在恢复不确定时写 `.recovery` journal 阻断后续操作。

> 注:fileguard **不做 MIME 嗅探**,它负责的是路径 == 文件系统安全边界。真正的「类型/扩展名」白名单在 `api/upload_policy.go`。

### 5.2 `api/upload_policy.go` — 扩展名白名单(文档上传)
- `defaultUploadExtensions`(`upload_policy.go:53-63`):安全默认白名单。**刻意排除**可执行包装(`.exe .dll .so .bin .jar .msi .bat .cmd .ps1 .sh`)、Office 宏文件(`.docm .xlsm .pptm`)、潜在 polyglot 压缩包(`.zip .tar .gz .7z .rar`)、可被内联渲染导致 XSS 的 `.html .htm .svg`;PDF 因强制 `attachment` 处置而允许。
- **图片家族无条件放行** `alwaysAllowedImageExtensions`(`upload_policy.go:102-104`):`png jpg jpeg jpe jfif gif webp bmp tif tiff heic heif avif ico`——管理员白名单只管文档/代码/数据,普通照片必须可用,且全部 attachment 处置 + 无脚本。
- 扩展别名 `extAliases`(`upload_policy.go:69-80`):`jpg↔jpeg` 等制表符,避免「允许 jpg 拒 jpeg」的常见坑。
- `validateUpload`(`upload_policy.go:184-224`):`filepath.Base` 去目录、拒 NUL/控制字符/隐藏文件/超长(>200B)、取**最后一个**扩展名(`report.pdf.exe` 按 `exe` 判),未命中白名单 → 400。所有上传路径**先校验再落盘**。
- `validateUploadRelPath`(`upload_policy.go:244+`):文件夹上传的相对路径校验——反斜杠->`/`、拒 `..`/空段/绝对路径/NUL,防目录逃逸。

> 注意:MIME 嗅探/恶意文件内容扫描不在上述两处;若复刻需要,建议补 `python-magic` 或 `file` 字节嗅探。

## 6. 出站安全(`netsafe/`)— SSRF 防护

`netsafe.go` 提供 SSRF 抵抗型 HTTP 客户端,核心是**拨号期对「解析后 IP」做校验**,击败 DNS-rebinding 与 redirect-to-internal:

- 额外拒绝段 `extraDeny`(`netsafe.go:29-51`):CGNAT(`100.64/10`)、NAT64(`64:ff9b::/96`)、TEST-NET、AWS metadata IPv6(`fd00:ec2::254/128`)等 Go 默认谓词不覆盖的内网/元数据段。
- `IsPublicIP`(`netsafe.go:57-65`):拒 loopback/private/link-local/unspecified/multicast + extraDeny。
- `IsUserMCPDialAllowed`(`netsafe.go:74-83`):**用户配置的 MCP 端点放行 RFC1918/私有 LAN**(协议要求能连内网),但仍拒 loopback(含 `169.254.169.254` metadata)/link-local/multicast/extraDeny。
- 工厂:
  - `SafeClient(timeout)`(`netsafe.go:135-137`):**公网 IP + 仅 80/443**,用于任意用户/模型驱动的抓取。
  - `PrivateBlockClient(timeout)`(`netsafe.go:142-144`):公网 IP、任意端口,用于半可信服务器间下载(如 MinerU 返回的对象存储 URL)。
  - `UserMCPAllowedClient(timeout)`(`netsafe.go:151-160`):用户 MCP 运行时传输,放行内网主机+任意端口,并加 redirect 安全策略。
- 拨号实现 `makeClient`(`netsafe.go:99-131`):`Dialer.Control` 在**每次连接**时对 `address`(host:port)校验端口与 IP;`CheckRedirect` 限 5 跳,且**每跳都被 Dialer.Control 重新校验**(防重定向到内网)。
- 用户 MCP redirect 安全 `checkUserMCPRedirect`(`netsafe.go:162-218`):拒跨域跳转、拒 `https→http` 降级(防凭据明文化),同权威主机才允许。

## 10. 计费模型(如何按 token/用量计费、定价)

`tokenprice/` 目录不存在;定价与计费逻辑分散在 `llm/quota.go`、`store/billing_usage.go`、`store/models.go`、`store/user_groups.go`。

### 10.1 模型价格字段(`store/models.go` / `channels.go`)
每个模型记录价格(最小单位的钱):
`price_input / price_output / price_cache_read / price_cache_write / price_per_image / currency`(`store/channels.go:288,335`)。

### 10.2 token 成本计算(`llm/orchestrator_automation.go:841-859`)
```go
func computeCost(m store.Model, u Usage) float64 {
	if m.Kind == "image" {
		return float64(u.OutputTokens) * m.PricePerImage   // 图片按张数
	}
	// openai.chat / openai.responses / gemini.generateContent 的 input 含 cache token
	inputTokens = maxInt(u.InputTokens-u.CacheReadTokens-u.CacheWriteTokens, 0)
	cost += float64(inputTokens)       / 1_000_000 * m.PriceInput
	cost += float64(u.OutputTokens)    / 1_000_000 * m.PriceOutput
	cost += float64(u.CacheReadTokens) / 1_000_000 * m.PriceCacheRead
	cost += float64(u.CacheWriteTokens)/ 1_000_000 * m.PriceCacheWrite
	return cost
}
```
**定价口径 = USD 每百万 token**(`PriceInput` 等以「每 1M token 的美元小数」配置,除以 `1e6`),图片按**张数 × PricePerImage**。

### 10.3 用量落库(`store/billing_usage.go`)
- `RecordBillingUsage`(`billing_usage.go:33-57`):记录 `cost_micros / images_count / input_tokens / output_tokens / currency` 到 `billing_usage` 表,**独立于**可被管理员修剪的诊断用 `usage_logs`。零成本行也保留(用于全站日限)。
- `TurnSideBillingCosts`(`billing_usage.go:62-76`):读某一 message 的 side-call(图片等)成本,防重复分类。
- `BillingImagesSince / BillingTokensSince`(`billing_usage.go:78-92`):按用户/时间聚合,用于日配额校验。

### 10.4 USD → 积分换算与扣减(`llm/quota.go`)
- `creditsPerUSD()`(`quota.go:460-466`)读全局设置 `credits_per_usd`(0 = 积分系统关闭)。
- `chargeTurnCredits`(`quota.go:491-508`):`credits = usdCost × credits_per_usd`,然后 `store.DebitCredits(userID, credits, "llm", "")`。
- `creditDecision`(`quota.go:470-486`):生成前预检余额 >0(可用余额)。`estimateRequestTokens`(`quota.go:525+`)用启发式(CJK 感知 `estimateTokens`)估计输入 token 做 pre-flight。
- **同类模式延伸到语音**:`audio_billing.go` 按 `audio_transcribe_price_per_second`(USD/秒)× `credits_per_usd` 计费,走「预留 → 结算」账本,两并发会话不会花同一余额;价格或汇率任一为 0 则免费;管理员不扣费(`audio_billing.go:1-24`)。PPT/文档生成同理(`aippt_handlers.go:589` 用 `cfg.CreditsPerPPT`)。

```
                       ├─ event 幂等(ON CONFLICT)
                       ├─ 加行锁 users FOR UPDATE
                       ├─ credit_package  → +永久 credits(credit_ledger)
                       └─ user_group      → 设 group_id/expires_at
                                           续期叠加(currentExpiry)
                                           切组存 previous_group_id
                      → 订单 fulfilled + 发会员邮件
```

- **对账兜底**:下单超时/状态未知(`IsCheckoutStateUnknown`)→ 订单 `processing`,靠 `Reconciler.Reconcile`/管理端对账闭环;EPay 用 `payment_order_attempts`,Stripe 可 metadata 反查。
- **计费扣减**发生于 LLM 调用(而非购买):`computeCost(USD) × credits_per_usd → DebitCredits`,支持「预留 → 按实际结算」的原子账本与重试防双扣。
- **无自动续费**:续费 = 再次购买(叠加 `group_expires_at`)。

## 12. Python 复刻要点(Go → FastAPI)

> 协议/字段层面保持一致的要点,已在各章标注;此处汇总实现选型。

### 12.1 支付(`payment/` → `payments/`)
- **保持 ISO 最小单位整数 + `AmountMinor` / `PaidAmountMinor` / `TaxAmountMinor` / `Currency` 字段与 JSON tag 不变**;用 `decimal.Decimal` 处理换算(等效 Go `math/big`),移植 `money.py` 的 `CurrencyExponent / ParseMinorAmount / ConvertMinorAmount`。
- **Stripe**:用官方 `stripe` Python SDK。
  - `stripe.checkout.Session.create(mode="payment", client_reference_id=order_id, ...)` 对应 `CreateCheckout`;`metadata={"order_id":...}`、`payment_intent_data["metadata"]`、`idempotency_key=order_id`。
  - webhook 验签:`stripe.Webhook.construct_event(payload, sig, secret)`(FastAPI 用 `stripe.WebhookSignature`)。注意 Go 用的是 `IgnoreAPIVersionMismatch:true`——Python 需自行容忍版本差异或统一版本。
  - 对账:`stripe.checkout.Session.retrieve`、`stripe.PaymentIntent.search(query="metadata['order_id']:'...'")` + `stripe.checkout.Session.list(payment_intent=...)`,映射 `retrieveStripeReconciliationSession`。需要 HTTPX 客户端注入(自定义 transport)或 monkeypatch,复刻 `stripe.Backends` 注入能力。
- **网关抽象**:定义 `Protocol`/ABC `CheckoutCreator`(`create_checkout`)与 `CheckoutResumer`(`resume_checkout`) + 一个 `Reconciler`,以及 `ProviderEvent` dataclass(字段:ID/Type/Status/OrderID/ProviderOrderID/ProviderPaymentID/AmountMinor/PaidAmountMinor/TaxAmountMinor/Currency/FailureReason)。
- **`IsCheckoutStateUnknown`**:移植分类逻辑(超时/挂断/5xx/网络错误 → 不确定),驱动订单 `processing`。
- **EPay**:`httpx` POST `submit.php` 表单;移植 `MD5` 签名(headers 之外按字典序拼接 + key,`epay.go:171-192`);验签用 `hmac.compare_digest`(等效 `subtle.ConstantTimeCompare`)。
- **Waffo**:移植 GraphQL 客户端(可用 `httpx`);验签用其公钥方案。
- **不可变结算快照**:订单存 `currency / conversion_rate / amount_minor`,履行时以快照为准(尤其 EPay/Waffo 跨币种)。

### 12.2 积分账本(`store/credits.go` → `credits/`)
- 用 **int64 微单位**(`1_000_000`)存储所有金额;`CreditsToMicros` 用 `round()` 并做 NaN/Inf/越界防护。
- 事务(依赖数据库 `FOR UPDATE` + `Serializable` 隔离)——FastAPI 用 SQLAlchemy `with_for_update()` / `isolation_level="SERIALIZABLE"`。
- 移植 `ReserveCredits / SettleCreditReservationByKey / ReleaseCreditReservation / DebitCredits` 状态机(`reserved→settling→settled|released`),这是**防双扣/防重试双计费**的关键。
- 表:`credit_ledger(kind=timed_debit|permanent_debit, cycle_anchor, cycle_start)`、`credit_reservations`。

### 12.3 邮件(`mail/` → `mailer/`)
- **SMTP**:`aiosmtplib`(异步,推荐)或 `smtplib`。复刻:
  - 端口 465/`tls=True` → `STARTTLS=False` 隐式 TLS;否则 `STARTTLS=True`(587/25)。
  - **超时**:`connection_timeout`,避免挂死(等效 `net.Dialer 10s`/`deadline 25s`)。
  - 仅在配置用户名且服务器支持 AUTH 时认证。
- **模板**:移植 5 语言文案与 HTML 模板。用 `Jinja2` 渲染;`reset` 链接与 `AppURL` 需校验 scheme/host。`Code`(验证码)与 `ResetURL`(token)**绝不写入日志**。
- **多账户路由**:`DeliveryConfig(accounts + rules)` → 每类邮件(purpose)选账户;`verify/reset` 强制启用。
- **队列**:Go 版是**同步同步发送**(每次 `SendAuth` 立即 smtp).复刻可用后台 worker/`asyncio` 队列避免阻塞请求,但**保持字段与模板一致**。
- 模板内联自包含(Table 布局 + 内联样式),复刻保持同一 HTML 结构以便兼容邮件客户端。

### 12.4 缓存(`cache/` → `cache/`)
- 定义 `Cache` `Protocol`(Get/Take/Set/SetNX/CompareAndDelete/Delete/TTL/Incr/IncrBy/Decr/Publish/Subscribe/StreamAppend/StreamRead/StreamAppendIfAllowed/StreamReadIfAllowed/StreamRevoke)。
- `redis-py`:`redis.asyncio.Redis`。
  - 原子性:用 Lua 脚本(`register_script`)复刻 `incrWithTTL / take / compareAndDelete / streamAppendIfAllowed / streamReadIfAllowed / streamRevoke`,`redis.asyncio` 的 `eval`/`evalsha`。或可用 `pipeline(transaction=True)` 近似,但 **Stream×denyKeys 和固定窗口 Incr 用 Lua 最保险**。
  - Stream 命令:`XADD ..., MAXLEN ~ 50000`、`XRANGE`、`XACK`(`StreamReadIfAllowed` 用 `XRANGE COUNT`,不阻塞消费)。
  - Pub/Sub:`pubsub()` 的 `subscribe` + 后台 bridge task(等同 `redis.go:246-269` 的 bridge goroutine,负责关闭 channel)。
- **内存版**:asyncio-safe dict + `asyncio.Lock`/`deque`;`Incr`/`SetNX`/`Take`/`CompareAndDelete` 需原子(单事件循环内可不用锁,但跨 task 建议锁)。
- 固定窗口 `Incr`:TTL 仅在首次创建时应用(Lua 已处理)。
- `Subscribe` 的「SUBSCRIBE 确认后再做 marker 检查」防丢首条信号的握手(Redis 用 `await sub.wait_for_pubsub_message`/`ping-pong`,或 `pubsub.subscribe` 后 `await` 一个确认)至关重要——复刻 `redis.go:233-241`。

### 12.5 对象存储(`storage/` → `storage/`)
- **抽象**:`ObjectStorage` Protocol,实现 `S3Storage`(boto3)、`AliyunOSS`(`oss2`)、`LocalStorage`。
- **boto3**:`put_object`(带 `ContentType`)、`generate_presigned_url("get_object", ExpiresIn=ttl)`、`delete_object`;兼容端点用 `endpoint_url` + `S3Config(s3={"address_style":"path"})`(等效 `UsePathStyle`,见 `s3_direct.go:221`)——minio/自建兼容。
- **oss2**:`bucket.put_object_from_file`、`bucket.sign_url('GET', key, ttl)`、`bucket.delete_object`。
- **local**:`AIVORY_LOCAL_STORAGE_DIR`,写文件时**必须做路径包含校验**(等效 `fullObjectKey` 拒 `\0/../\`, `s3_direct.go:303-317`)。
- **路径策略**:一律自动加 `Prefix`(默认 `workspaces/`),`PutResult{Provider, Key, URL, ExpiresIn}` 字段保持。
- TTL 夹取(默认 1h,上限 24h)与 sidecar 模式的 base64 载荷可选保留(若复刻 sidecar 则移植)。
- 大文件(MinerU 200MB)用「直传」路径避免 proxy 中转。

### 12.6 上传/路径安全(`fileguard` + `upload_policy`)
- 移植 `fileguard` 路径函数:`Relative / ResolveExisting(EvalSymlinks + 拒绝非 regular file) / PrepareWrite`(逐段 Lstat 拒 symlink)——`pathlib` + `os.path.realpath`。
- 移植 `upload_policy`:扩展名白名单(src、docx、png…)、图片家族无条件放行、`jpg↔jpeg` 别名、取最后一个扩展名、拒 NUL/控制字符/隐藏文件、`validateUploadRelPath` 拒 `..`/绝对路径。
- (可选增强)MIME 嗅探:`python-magic`/`file --mime-type` 做内容级校验(Go 版未做,建议补)。

### 12.7 出站安全(`netsafe/` → `netsafe/`)
- 复刻「拨号期解析 IP 再校验」:Python 需要自己实现——用 `ipaddress` 判定 + 自定义解析/连接。方案:
  1. 预解析 + 校验:先用 `socket.getaddrinfo` 解析全部 A/AAAA,若有私有/元数据 IP 则拒绝(防 DNS-rebinding)。更严格的是**连接前再解析一遍校验**(比 Go `Dialer.Control` 略弱,Go 在真正的 fd 级强制)。
  2. 或用 `aiohappyeyeballs`/自定义 `asyncio` 连接器注入校验;对 `httpx` 可用自定义传输/连接池,在 `connect` 阶段校验 IP。
- 移植 `IsPublicIP`(+`extraDeny` 列表:CGNAT/NAT64/TEST-NET/metadata)、`IsUserMCPDialAllowed`、`SafeClient(仅80/443)`、`PrivateBlockClient`。
- redirect 策略(限 5 跳、拒 `https→http` 降级、用户 MCP 拒跨域)→ `httpx.FollowRedirects` + `event_hooks`/自定义。
- **必须拦截 cloud metadata**(`169.254.169.254`、`fd00:ec2::254`),并处理 IPv4-mapped IPv6(`::ffff:169.254.169.254`)。

### 12.8 PDF 导出(`pdfexport/` → `pdfexport/`)
- Go 用 chromedp;Python 两大替代:
  - **Playwright**(最接近):`page.set_content` → `page.pdf(format="A4", print_background=True, margin=..., display_header_footer=True, header_template="<span></span>", footer_template="...pageNumber/totalPages...")`;`page.route` 拦截全部网络/文件请求返回 abort(等效 `SetBlockedURLs`);浏览器上下文隔离 + `context_params`。配合 `asyncio.Semaphore(2)` 限并发;`page.pdf` 同时隐式等待字体图片(需 `page.evaluate` `document.fonts.ready`)。
  - **WeasyPrint**(纯 Python,更简单、无浏览器):渲染自包含 HTML→PDF,支持 `@page` 边距/页脚 `counter(page)`。**注意**:不执行 JS,且外部资源默认不加载(本身即安全),但样式/字体支持不如 Chromium——若 Aivory 页面纯静态表格/文字,WeasyPrint 足够且更轻。
- 无论选哪个,**必须保留**:
  - 强 CSP(`default-src 'none'` 等)注入;
  - 阻止外网/文件网络请求与脚本执行(反 SSRF);
  - 输出体积上限(32MB);
  - 并发限制(2 tab)与超时(40s)。
- 页脚 `Aivory · <pageNumber>/<totalPages>` 需复刻。

### 12.9 配置(`config/` + `envcfg/` → `settings/`)
- 用 **`pydantic-settings`**(`BaseSettings`)承载 `Config`;字段即 `config.go` 的所有成员(Listen/Env/DatabaseURL/RedisURL/VectorBackend/Qdrant/JWT secret/AccessTTL/目录/配额/搜索/embedding/sandbox/MinerU/OAuth/Updater…)。
- 环境变量前缀:`AIVORY_*`(部分用裸名如 `DATABASE_URL`/`JWT_SECRET`,需显式 `Field(validation_alias=...)` 映射大小写兼容)。
- 用 Pydantic `field_validator`/`model_validator` 复刻:
  - `ResolveVectorBackend`(auto/qdrant/sqlite/disabled,`config.go:219-245`);
  - `Validate` 部署检查(`looksDeployed`:非 dev 或 Postgres → 强制 JWT_SECRET≥32 且非默认,`config.go:175-207`);
  - `envcfg` 的「未设置/解析失败用默认」语义 = Pydantic 默认值天然满足;`AIVORY_*` 高级覆盖与主配置对齐。
- 用 `pydantic-settings` 的嵌套模型表达 `StorageConfig`(provider/prefix/s3/oss)与 `DeliveryConfig`(accounts/rules)。

### 12.10 自定义头(`requestheaders/` → `httpx/headers`)
- 移植 `Normalize`(≤64 头、合法 token 字符、拒控制字符、拒 `Content-Length/Transfer-Encoding/Trailer`、拒大小写重复、≤16KiB)。
- `httpx` 发送时 `Headers`;`Host` 需写 `request` 的 `headers["Host"]`(httpx 允许显式设置)。

### 12.11 计费/配额移植
- `computeCost`(`orchestrator_automation.go:841`)直接翻译为纯函数;`credits_per_usd` 读数据库设置。
- `billing_usage` 表与 `billing_usage.go` 的 `RecordBillingUsage / TurnSideBillingCosts / BillingImagesSince / BillingTokensSince` 用 SQLAlchemy 复刻。
- 图片按张数、文本按「USD/百万 token」的字段语义与 `CreditsToMicros/De bitCredits` 保持一致。
