# Aivory 前端整体架构与状态管理调研

> 配套：《00-整体架构与技术栈.md》《后端-01-API路由与认证授权.md》。
> 本文档聚焦 **React 前端 Web 应用（`src/`）的整体架构**：入口与路由、API 客户端层、状态管理、页面地图、实时事件消费。**复刻关键：只要新 Python 后端在 HTTP 端点、鉴权头、请求签名、SSE 事件格式上与此处一致，React 前端可以零改动复用。**

---

## 1. 技术基础

- **框架**：React 18 + TypeScript + Vite（`tsc -b` 类型检查，`vite.config.ts`）。
- **路由**：`react-router-dom`（`BrowserRouter`，`useTransitions={false}`）。
- **状态**：**Zustand**（`create` from `'zustand'`，见 `src/store/*.ts`）。
- **HTTP**：自研 fetch 封装 `src/api/client.ts`（无 axios）。
- **样式**：Tailwind CSS 4 + 语义 token（`src/styles/tokens.css`）。
- **富文本/代码**：TipTap 3、CodeMirror 6；office：`@pptx-renderer`、`@docx-editor.dev` 等。
- **i18n**：自研（`src/i18n/`）。
- 桌面端通过 `window.aivoryDesktop` 桥接（`import.meta.env` / `VITE_AIVORY_DESKTOP`）。

## 2. 入口与启动流程

`src/main.tsx`：
1. 引入自托管品牌字体（Fraunces / Geist Variable，**不依赖 Google Fonts CDN**，可过 GFW）。
2. `import './i18n'` 初始化多语言。
3. `import '@/store/accent'` —— eager init，在首次渲染前给 `<html>` 设置 `data-accent`。
4. `import './styles/globals.css'` + `katex` 样式。
5. `createRoot(root).render(<StrictMode><StartupBoundary><BrowserRouter><App/></BrowserRouter></StartupBoundary></StrictMode>)`。

启动屏 `StartupBoundary`（`src/components/ui/startup-screen`）在应用 hydrate 前显示内联的启动 token（见 `vite.config.ts` 的 `startupAssets` 裁剪一份最小 token 集内联）。

### 构建期注入
`vite.config.ts`：
- 每个生产构建带唯一 `__APP_VERSION__` 版本 id 并写入 `dist/version.json`，前端 `src/lib/app-update.ts` 据此对比，部署后安全时刻自动刷新（`src/lib/app-update.ts`）。
- `releaseVersion` 来自 `package.json` 的 version（About 页显示的是发布版本）。

### 4.2 baseURL 与鉴权（`client.ts`）
```ts
const API_BASE = window.aivoryDesktop ? '/api' : (import.meta.env.VITE_API_BASE) ?? '/api'
```
所有请求发给 `API_BASE + path`（默认同源 `/api`，开发时由 `vite.config.ts` 代理转发）。

**双通道鉴权**（关键）：
1. **Cookie**：所有请求 `credentials: 'include'`，携带后端设置的 **httpOnly 刷新 cookie**（长生命周期，`Path` 限定 `/api/auth`）。
2. **内存 access token**：登录后把短生命期 access token 保存在内存（`memoryToken`），每个请求带 `Authorization: Bearer <jwt>`。

### 4.3 请求签名（v2 HMAC）—— 复刻必须实现
`client.ts:119-154` 的 `authenticatedRequestHeaders` 为每个带 token 的请求附加一次性防重放签名：
```
x-device-id, x-client-id
authorization: Bearer <jwt>
x-req-ts        = unix 秒
x-req-nonce     = 随机 base64url(16B)
x-req-content-sha256 = sha256(请求体) 或 'UNSIGNED-PAYLOAD'(表单)
x-req-token     = HMAC-SHA256(requestSigningKey, 
                      "v2\0ts\0nonce\0METHOD\0canonicalPath\0deviceId\0payloadDigest\0sha256(jwt)")
```
- 签名密钥（`requestSigningKey`）由登录/刷新接口随 access token 一起下发（后端持有原始密钥，每小时 epoch 派生一次：`_dk` 用 `floor(ts/3600)` 派生密钥）。
- 服务端**一次性消费 nonce**、绑定方法/路径/设备/负载，防重放与防篡改。
- 无 `crypto.subtle` 的非安全上下文（LAN IP http）回退到纯 JS HMAC（`src/lib/hmac-sha256`）。
- **这对 Python 后端是硬性要求**：必须在登录/刷新响应下发对应签名密钥，并在鉴权中间件中验证 `x-req-token`（详见《后端-01》的 v2 签名一节）。

### 4.4 401 自动刷新（single-flight）
`client.ts:249-312`：请求遇 401（且非 `/auth/` 路径）会触发一次刷新——`tryRefresh()` 调用注册的 handler（auth store 提供的 `/api/auth/refresh`），**single-flight**（多个并发 401 共享一次刷新），成功后重放原请求一次。刷新失败不会无限重试。
- 特定错误消息触发全局副作用：`auth required` / `session expired` → 登出提示；`account_suspended` → 封禁提示；`initial_password_required` → 首次密码必改；`site_closed`（503 + `{error:"site_closed"}`）→ 站点下线事件。

### 4.5 SSE 流式消费（复刻协议核心，详见前端-02）
- **`streamSSE(path, body, signal)`**（POST 生成流）：`fetch` + `ReadableStream`，按 `\n\n` 分帧解析 `event:`/`data:`/`id:`，把 data JSON.parse 后 `yield {event, data, id}`。**创建型 POST 流不做自动重试**（重发会二次生成）。
- **`streamSSEGet(path, signal, lastEventId, opts)`**（GET 事件流）：可**自动重连**（指数退避 1s×2^(n-1)，最多 3 次），带 `Last-Event-ID` 断点续传；读到 `data.type === 'done' | 'error'` 即正常结束。
- 鉴权与请求签名同样应用于 SSE（`accept: text/event-stream`）。

### 4.6 文件上传
`apiUpload` 用 **XHR**（fetch 无上传进度事件）+ FormData，同样带签名头，支持 `onProgress` 与 abort；桌面端经 `x-aivory-desktop-request` 桥接。

## 5. 状态管理（Zustand）

`src/store/` 共 23 个独立 slice（`create` from `'zustand'`），无 Redux。清单与职责：

| Store | 职责 |
|---|---|
| `auth.ts` | 登录态、用户、hydrate、login/register/logout 三态、401 刷新 handler、封禁/首次密码回调 |
| `conversations.ts` | 会话/消息、当前线程、流式追加、分支 |
| `workspaces.ts`、`projects.ts`、`sidebar-projects.ts` | 工作区与项目 |
| `models.ts` | 模型选择/能力 |
| `settings.ts`、`settings-modal.ts` | 外观/模型/隐私设置 |
| `theme.ts`、`accent.ts` | 主题与强调色 |
| `ui.ts`、`composer-prefs.ts` | UI 与输入偏好 |
| `aippt.ts` | AI PPT 状态 |
| `artifact-panel.ts`、`html-preview.ts` | 产物/HTML 预览面板 |
| `conversation-files.ts`、`sandbox-files.ts` | 会话/沙箱文件 |
| `inline-thread.ts`、`queued-turns.ts` | 内联线程、排队轮次 |
| `domain-data.ts`、`language.ts`、`notification-center.ts`、`reply-notification-preferences.ts`、`site-status.ts` | 领域数据/语言/通知/站点 |

**特点**：
- `auth.ts` 用 `authOpSeq` 递增序列防止并发 auth 操作互相覆盖（登录期间旧 hydrate 的 401 不误登出）。
- 客户端不持久化 access token（内存），刷新靠 httpOnly cookie 兜底。
- `setRefreshHandler`/`setAuthLostHandler`/`setBannedHandler` 等回调由客户端注册，`client.ts` 保持无循环依赖。

**Contexts**（`src/contexts/`）用于少量跨组件共享（非全局状态）。

## 6. 实时事件消费（跨设备同步）

前端通过 `GET /api/events`（SSE，见 `streamSSEGet`）订阅后端实时事件，用于：
- 跨设备会话更新（`conversation.updated`）。
- 通知（`notifications.ts`）。
- 生成进化/压缩状态事件（`conversation.updated` / `compaction` 事件）。
- 站点状态变化。
`data.type === 'done' | 'error'` 作为流结束信号。

这与后端 `cache` pub/sub、`genstream`（`gen:<id>` + 撤销墓碑 + 跨进程 pub/sub）协同（见《后端-02》）。

## 7.「与 Python 后端复刻的接口约定」（前端零改动的前提）

要让 React 前端**不改一行**连上新的 Python 后端，必须满足：

1. **端点路径与方法**：`/api/...` 全部路径、方法与 `router.go` 一致（后端-01 的路由表是权威清单）。前端通过 `endpoints.ts`/`client.ts` 调用，动态拼接路径。
2. **鉴权**：
   - 下发/刷新**双 token**：内存 access token（Bearer）+ httpOnly 刷新 cookie（`Path=/api/auth`，`credentials: include` 往返）。
   - 登录/刷新响应携带前端**请求签名密钥**，并校验每个请求的 `x-req-ts/x-req-nonce/x-req-content-sha256/x-req-token`（v2 签名，一次性 nonce）。
   - 错误消息语义：`auth required`、`session expired, please log in again`、`account_suspended`、`initial_password_required`、`site_closed`（503）。
3. **JSON 字段**：与 `src/api/types.ts` 的 `Api*` 类型字段名（camelCase）完全一致。
4. **SSE**：
   - 生成流：`POST /api/conversations/:id/messages` 返回 `text/event-stream`，事件含 `event:` + `data:` JSON（`delta/thinking/tool_logs/done/error/artifact/...`），帧以 `\n\n` 分隔。
   - `GET /api/events` 长连接事件流，支持 `Last-Event-ID` 断点续传，`done/error` 结束。
5. **错误响应形态**：非 2xx 返回 JSON `{error: string}`（及其他字段），前端 `ApiError` 依此解析。
6. **CORS / 代理**：开发由 vite 代理 `/api`；部署需同源或配置 CORS + `ALLOWED_ORIGINS`。

**建议**：新后端先以 `src/api/types.ts` 为 Pydantic schema 蓝本，以 `router.go`（后端-01）为路由蓝本，保证上述契约；再用仓库 `tests/browser/*.mjs`（Playwright）对原前端做逐阶段冒烟验证。
